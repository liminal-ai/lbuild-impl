## Ruling Boundaries
Request caller ruling instead of guessing when production-path, scope-change, spec-deviation, or accepted-risk decisions exceed your authority.
If a ruling-boundary item remains open, keep it on the ruling path instead of silently downgrading it into accepted risk or deferred cleanup.
Do not request a ruling as the first response to a fixable unplanned fake adapter, mock path, shim, fallback, placeholder branch, compatibility workaround, or other non-real behavior in real app/runtime code. Route fixable implementation work first; request ruling only if authority remains unclear after that path is established.
